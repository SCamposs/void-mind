Each package includes an adjacent SHA-256 checksum and updater signature verified against Mind's own updater public key. Linux has separate DEB/AppImage routes; DEB updates use the system package manager and may request administrator authorization.

## Added

- Check for updates when Mind opens and every hour. Settings can disable automatic checks and keep manual **Check now** available.
- A branded Base UI dialog for update announcements, **Later**, explicit **Update and restart** confirmation, release information and actual download progress.
- Persistent manual-check preference. Choosing Later avoids repeatedly opening the same version's dialog during the current session.
- Retry handling for network/installation failures and restart-only retry after installation succeeds.
- A separate signed update feed and release assets for VOID Mind. The updater does not depend on the standalone VOID app or any AI provider.

## Windows installation

Updates run quietly for the current Windows user, without an install-scope selection page. Mind explains that it will close and restart before installation begins. Download progress is shown in the app; after Windows takes over installation, the app may be closed until it restarts.

Windows installers are **not Authenticode-signed**, so SmartScreen may display a warning. The updater's cryptographic signature is a separate mechanism. Download only from this repository and verify the supplied checksum.

## Upgrading from alpha.1

**Download and run this installer once.** The alpha.1 application did not include the updater. This version adds the update mechanism for subsequent releases. Existing conversations, settings and connections are not intentionally reset by this change; actual upgrade and restart acceptance remains open in [#6](https://github.com/SCamposs/void-mind/issues/6).

The application/release version is `0.2.0-alpha.2`; native package and updater versions use `0.2.0-2`, continuing the previous numeric prerelease mapping. This is not a stable 0.2.0 release.

## Validation and follow-ups

Updater state-machine tests cover scheduling, persistence, consent boundaries, failures, retries and resource cleanup. Component tests cover postponement, confirmation and determinate/indeterminate progress. CI validates the frontend and native application and packages Windows NSIS plus Linux DEB/AppImage files.

Manual Windows/Linux upgrade, restart and installer acceptance is tracked in [#6](https://github.com/SCamposs/void-mind/issues/6). Existing [provider and platform follow-ups](https://github.com/SCamposs/void-mind/issues) remain unchanged. No new inference, training, title-generation or provider behavior is introduced.
